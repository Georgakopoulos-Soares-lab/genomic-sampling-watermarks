# Mechanised audit, 2026-08-23

A step back over everything admitted so far, run as scripted checks against the artifacts rather than
as a re-reading of summaries. Ten checks, then four real defects found and fixed, one false alarm the
audit raised against itself and corrected, and a gap list that is now explicit.

Defects 3 and 4 were found later the same day, while building the E8/E9 comparison, by writing a fresh
validator and pointing it at existing code. They are recorded here rather than in a separate document
because they belong to the same sweep.

## What passed

| Check | Result |
|---|---|
| Ledger structure | 76 entries, no duplicate ids, statuses only `V` and `A` |
| Cited artifacts exist and digests match | 70 artifacts, zero missing, zero mismatches |
| Superseded artifacts no longer cited | zero citations of any superseded version |

## Defect 1: detection-rate intervals ignored the threshold's uncertainty

A detection rate is measured against a threshold **estimated** from null trials. The intervals
resampled only the positive prompt clusters, which treats that threshold as known.

Measured impact on E5: 29 of 84 curve cells had understated intervals, by up to 3.6 times on marginal
cells. Worse, eight unanimous cells reported a *degenerate* interval — for example `C_tok` substitution
at rate 0.15 and 1,536 bases claimed [1.000, 1.000] when the honest interval is **[0.875, 1.000]**.
That is a claim of certainty the data does not support, on a headline cell.

**Fixed.** `joint_detection_rate_interval` resamples the nulls, recalibrates the threshold from that
resample, and independently resamples the prompt clusters, preserving clustering by averaging within
a cluster. `scripts/recompute_detection_intervals.py` recomputes every cell from the stored per-trial
rows, so **no experiment was re-run** — the trials were stored for exactly this reason.

624 interval fields across 312 curve points were replaced in E5, E6, E7 stage 1, and E7 stage 2. A
structural diff confirms nothing outside the interval fields changed, and a round-trip check confirms
every patched bound equals its recomputed value.

**No point estimate moved**: not one detection rate, threshold, achieved false-positive rate, largest
fully detected rate, or separation flag.

## Defect 2: artifact digests were not reproducible by re-running — fixed

Re-running a recorded command produced byte-different output while every scientific value was
identical. The only differing field was `wall_seconds`. So a file digest identified the **stored**
artifact, which detects tampering, but "re-run and compare digests" did not work.

**Fixed.** `src/genomic_watermarks/content_digest.py` computes a digest over the artifact with the
volatile fields removed — timings, memory, host identity — and with recorded path *spellings*
removed, because every path in these artifacts is accompanied by a digest of that file's contents and
the digest, not the spelling, is the input's identity.

Two guards keep this from becoming a way to hide a changed result. `PROTECTED_FIELDS` names the
fields that may never be excluded and `assert_no_scientific_field_is_volatile` fails if the excluded
set ever intersects it. And `test_a_different_input_still_changes_the_digest` confirms that dropping
the path spelling did not make the digest blind to a changed input, because the accompanying content
digest still moves.

Verified end to end: re-running the E4 short-length detection pilot and the E8/E9 short comparison
produced byte-different files whose content digests matched exactly. `outputs/content_digests_v1.json`
records both digests for all 82 cited JSON artifacts, and `scripts/content_digests.py --expect`
re-verifies that table.

One detail worth keeping: the first rerun attempt *failed* the content-digest check, and it was right
to. I had omitted `--cohort-manifest`, so the rerun really was a different command with a different
recorded input. The digest caught it.

## Defect 3: the joint interval depended on the order the nulls were pooled

Found while writing the E8/E9 validator, which recomputed a cell from a differently ordered pool and
got different bounds.

The joint interval resamples the pooled nulls **by index**, and the pooled list is built by
concatenating two null families. So the bounds depended on which family came first — information that
carries no meaning — and two honest recomputations of the same admitted cell could disagree.

**Fixed.** The nulls are sorted before resampling, so every bound is a function of the null multiset.
Statistically nothing changes, because the resample draws uniformly from the multiset either way.

Effect on the ledger: of 327 interval-bearing points, 35 bounds moved, none by more than 0.025, which
is one resampling step on a 40-trial cell. No point estimate moved and no interval changed which side
of a conclusion it falls on. `scripts/canonicalize_detection_intervals.py` did the recomputation, and
it re-parsed the patched file to confirm every bound equals its canonical value and that the patch
changed only floats.

A second change came out of the same work: the interval's threshold is now computed as an order
statistic rather than by the quadratic scan `calibrate_threshold` uses, because recalibrating on
20,000 replicates made the scan prohibitive. The two are proven equal on 24,000 randomised inputs
including all-ties cases, and that proof is a permanent test rather than a one-off check.

## Defect 4: a validator was rejecting the very run it was supposed to check

`validate_detection_report` required every trial to have searched exactly 96 hypotheses. That is
wrong at the detector's own floor: a non-zero phase drops the final incomplete k-mer, so at 16 tokens
only phase zero is long enough to score and the true count is 16.

The consequence is that the E4 short-length artifacts **could not pass their own validator**, so the
96-base rows in the ledger were admitted without that recomputation ever running. My earlier audit
pass missed this because it checked that artifacts and digests existed, not that each validator
actually accepted its own artifact.

**Fixed**, and then the artifacts were re-validated. All three E4 short-length artifacts now pass, and
all 15 admitted E4 short-length points recompute exactly — thresholds 3.000, 3.545, 3.772, 3.355,
3.654 for `C_tok` and detection rate 1.0 throughout. **The evidence was correct; only the checker was
wrong.** No ledger value changed.

The lesson generalises: an unused validator is indistinguishable from a passing one. Every validator
should be run against every artifact it claims to cover, and that is now part of the standing
validation sweep.

## A false alarm the audit raised about itself

An early check reported that the 96-base clean-detection interval should be [0.500, 1.000] rather than
[1.000, 1.000], which would have overturned the short-length conclusion. That was **wrong, and it was
my own analysis error**: the ad-hoc check pooled the `any_key_public_dna` family into the null set,
which the experiment does not do. Recomputing with the nulls pooled exactly as the experiment pools
them gives [1.000, 1.000] for every E4 and short-length cell, because their margins are large.

Recorded because an audit that only reports the target's errors and not its own is not an audit.

## Gaps, stated plainly

None of these is an error. Each is scope that the objective names and the evidence does not yet cover.

| Objective question | State |
|---|---|
| What each released policy samples | **Partial.** `C_tok`, `G_tok`, `G_bp` are audited and pinned. Carbon's `C_deployed` processor stack is unresolved, so the released-deployed Carbon policy is not characterised. |
| Marginal preservation per construction | `partition_mc` covered for all three policies. `its` and `exp` now have model-backed generation and a matched calibrated comparison (E8/E9), though one-step marginal preservation for the two baselines rests on their invariant tests rather than on a model-backed E3-style run. |
| Information per token and per base | Covered for all three policies. |
| Detector calibrated over the full search | Strand, phase and key-offset covered. A sliding **observed** window appears only in E7 stage 2. Spliced or partial watermarking is never measured. |
| Edit classes | Substitutions, insertions, deletions, crops, reverse complementation covered. **Adaptive removal not done.** |
| Claim classes distinct | Maintained. |

Further gaps:

- **Cohort breadth.** E2 used all 24 prompts. Every detection experiment uses 8 prompts across four
  organisms. That narrowing is declared in each protocol but it means all detection and robustness
  numbers rest on 8 clusters, which is also why several intervals are coarse.
- **Biological proxies.** `docs/baseline_definition.md` declares ORF summaries and independent-model
  likelihood; neither is implemented. Only composition and complexity proxies exist.
- **Peak memory.** Not admitted, and not measurable with current instrumentation.
- **`G_bp` distinguisher signal.** Two nominal rejections, unresolved. Eighteen additional matched
  draws were queued on 2026-08-23 and stopped without producing any artifact: on battery power the MPS
  device runs generation at about a tenth of its mains speed, so the job needed tens of hours instead
  of five. Recorded in `e10_unkeyed_distinguisher_protocol.md` with the exact command. A consequence
  worth carrying: no runtime figure may be quoted without naming the power state, and the admitted E14
  wall times were all mains-power measurements.
- **Calibration transfer.** E8/E9 found that natural public DNA exceeds thresholds calibrated on
  model-generated nulls at rates above the 0.01 target, worst for the two baselines (`its` 0.069 at
  192 bases on `C_tok`). Reported as an observation, not a tested hypothesis.

## The pattern worth carrying forward

Six pieces of statistical machinery have now been replaced after a result looked wrong rather than
merely surprising: a non-strict decision rule, an unsigned drift range, a bootstrap ignoring
within-prompt noise, a sign-flip null ignoring a shared fitted direction, an interval ignoring
threshold uncertainty, and an interval that depended on the order its nulls were pooled. Every one was
caught by a number that was too clean or by a recomputation that disagreed with itself, and every one
was settled by reproducing the procedure on data whose truth was known.

Two of the six were found by *writing a new validator for a new experiment* and pointing it at old
code. That is the cheapest bug-finding move available here and it should be repeated deliberately.

The standing rule in `CLAUDE.md` follows from that: treat a new resampling scheme as suspect until its
null has been reproduced on synthetic data of known truth. To it add a second rule this audit
supplies: when a check disagrees with an admitted result, verify the **check** against the experiment's
own pooling before believing it. And a third: run every validator against every artifact it claims to
cover, because a validator nobody ran looks exactly like one that passed.
